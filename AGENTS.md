# Notes for coding agents

OpenLF2 reimplements Little Fighter 2 v2.0a. A C++23 engine (src/) runs the game, and Lua scripts (scripts/) hold the gameplay, the AI, the modes and the menus. The game reads the original data from the LF2 installer in memory and never runs it. The plan for network play is in plan.md.

This checkout is local only. Do not push it, and do not open pull requests from it: the `arena` branch holds private notes (this file, docs/upload-to-nextcloud.md) and paths of this machine.

## Build

Linux, debug (dependencies from the system, SDL3_ttf fetched by CMake):

```sh
cmake --preset debug -DOPENLF2_FETCH_SDL3_TTF=ON
cmake --build --preset debug
```

The build copies scripts/ next to the program (build/debug/scripts). After a script change, build again, or run with `--scripts scripts`.

Windows, cross-compiled on this machine (MinGW-w64, dependencies in ~/programs/openlf2-windows/prefix, built by build-deps.sh there):

```sh
W=~/programs/openlf2-windows
export PKG_CONFIG_LIBDIR=$W/prefix/lib/pkgconfig
cmake -S . -B build/windows -G Ninja -DCMAKE_TOOLCHAIN_FILE=$W/mingw-toolchain.cmake -DCMAKE_BUILD_TYPE=Release \
    -DOPENLF2_DEPENDENCY_PROVIDER=system -DOPENLF2_FETCH_SDL3_TTF=ON -DCMAKE_PREFIX_PATH=$W/prefix \
    -DOPENSSL_ROOT_DIR=$W/prefix -DZLIB_ROOT=$W/prefix "-DCMAKE_EXE_LINKER_FLAGS=-static-libgcc -static-libstdc++" \
    "-DCMAKE_CXX_STANDARD_LIBRARIES=$W/prefix/lib/libSDL3.dll.a"
cmake --build build/windows
```

`~/programs/openlf2-windows/publish-version.sh` builds both platforms, packs them and publishes a game version to the Nextcloud versions folder (docs/upload-to-nextcloud.md). `--dry-run` packs without upload. The latest version is 2026.10.25-37 (29fdd48).

All targets build with `-Werror`. Fix warnings, do not turn them off. A known GCC 13 false positive in src/app/versions.cpp has a local pragma with the reason.

## Run and test

The LF2 installer is in ~/.local/share/OpenLF2/LF2_v2.0a.exe on this machine. A headless input trace runs frames without a window and prints the state of the active screen (`describe`) at the end:

```sh
I=~/.local/share/OpenLF2/LF2_v2.0a.exe
build/debug/openlf2 --headless --installer $I --scripts scripts --seed 1234 --input-trace ",,#13,,#13,,,,c"
```

- A comma ends a frame. `udlrcbf` are the keys of player 1 (up, down, left, right, attack, jump, defend), `#N` holds virtual key N, `@X_Y` moves the pointer and `!` holds the left button. `=ID` clicks the menu element ID (Dear ImGui) and `=ID:N` sets slider ID to N, also in headless runs. `--seed` makes runs repeat.
- "game start" opens the match setup screen (base/ui/setup_screen, base/game/setup) in place of the title menu. Its buttons open the other modes, the championships, the demo and a replay, and Exit goes back to the launch menu (to the lobby in a network game). With keys: attack joins, the arrows move on the fighter grid, attack chooses, left and right set the team, attack is ready. Then up and down move between the arena, the difficulty, the computers (attack adds one) and the start, and defend starts a countdown of 90 frames. A VS fight with one computer: `W=$(printf ',%.0s' $(seq 1 40))`, then `",,#13,,#13,,$W,c,,,r,,,c,,,r,,,c,,,u,,,c,,,d,,,c"` and 120 frames. `--classic-menus` keeps the classic character selection. In a server session the server decides for every client: the setup screen, or the classic selection with `openlf2 --server --classic-menus` (tools/test-online.sh uses it for the traces of the original menus). There a click becomes a command that the server puts into the next final tick (`commands`), keys act on every client through the combined input, and any player starts. A command acts only for the sender's own slot or for a computer slot. The server keeps the values of the last match (mode, difficulty, arena, stage group, speed, transform rule) in its config.json (`last_setup`), and the next session starts with them. Every fighter is selectable. The switch "Transform at any HP" (`=free_transform`, off by default) gives the fight the rule of the original's `lf2.net` word: Firen and Freeze merge and Louis turns into Louis EX at any hp (`match.free_transform`); without it they need 177 hp or less.
- To a VS fight with the classic menus (`--classic-menus`): `W=$(printf ',%.0s' $(seq 1 40)); C=$(printf ',%.0s' $(seq 1 170))`, then `",,#13,,#13,,,,c,,,,c,,,,c$W,c,,,,c,,,,c,,,,c$C,c,,,,c,,,,c,,,,c$W,u,,,,u,,,,c$W$W"`. Item 0 in the output is player 1.
- Game speed 0.4: `--game-speed 0.4`. In a game, the speed is a slider of the settings menu (Escape); in a server session any player sets it for everybody (`set_speed`), and the fights skip ticks by it (base/game/speed_gate).
- Network: start one program with `--host 127.0.0.1 --port N` and one with `--join 127.0.0.1 --port N`, each with a headless trace of the same length. Both must print the same state. In a network trace, a frame that waits for the other computer runs its trace frame again, so held keys repeat.
- AI (docs/ai.md, docs/ai-plan.md): `--ai-log` (or `--ai-log 11,12` for item indices) prints the decisions of the computer fighters of the shown fight as `ai t=TICK i=ITEM ev=...` lines (headless: `frame N: action log ai ...`, so use `grep -o 'ai t=.*'`). `--ai-brain idle` gives the computer fighters of local fights another brain (base/ai/brains). A brain other than `classic` keeps its memory in `value.ai` and its own random stream, and the description shows `ai=BRAIN/DETAIL` on its fighter. The demo, replays and network sessions always use `classic`, and a local fight with another brain makes no recording. `--ai-brain 11=sentry` gives one item its own brain: the test brain `sentry` stands still and logs its predicted threats and the hits that it takes, and `tools/ai_prediction_check.py LOG` compares them. `--ai-view` (or F10 in a fight) shows the development view of the AI: hit boxes, body boxes, frame classes and the ticks to the next threat. `--ai-book` (or `--ai-book 11`) prints the AI's move book (base/ai/move_book) as `book ...` lines on the first frame, and `tools/lf2_moves.py ~/games/LF2 --check LOG` compares them with the data files.
- Rollback: `--rollback-check` makes each fight save its state every 45 ticks, run 8 ticks, go back and run them again. The headless description of the match then shows `rollback=checks:N,failures:F,...`. F must be 0. `differ=` names the fields of the first failure.
- Simulated network: `--net-sim delay=80,jitter=30,loss=5,seed=1` runs each fight through two rollback clients and a server in one program (base/game/netsim). Player 1 is client A (shown), the other players are client B (`c/r` in a trace gives player 2 the keys after the slash). The match description shows `netsim=a:...,hashes=CHECKS/FAILURES;b:...;server:...`. FAILURES must be 0.
- Server program: `openlf2 --server --installer $I --scripts scripts --port N` runs the server (UDP, ENet) without a window and prints its log. A client joins with `--connect 127.0.0.1 --port N` (or Network Game in the game: host starts a server on this computer). In the lobby, player 1's attack is ready, and the defend of any player starts a session when everybody is ready. No player has more rights than the others. A session runs the whole game on the server's final ticks: the menus in lockstep (base/game/online `exchange`), the fights with rollback. The server runs a frame on each message and at least every 4 ms. With `--upnp` (a hosting game passes it, unless `OPENLF2_NO_UPNP=1`) it opens its UDP port on the home router, and the lobby shows the public address. A game that hosts starts it with `--stop-with-parent`, so it stops when the game ends, also by a crash. With `--headless --input-trace`, a connected client paces its trace frames at 33 ms. The fight description shows `online=...,sent=HASHES,fights=N`. The server logs `hashes agree`, and on a desync `desync in the fight at tick T between A and B: ...` with the summary values, the fields and the items that differ (docs/netcode.md "Desync checks"). The menus have a check too: after every 30th session tick each client sends the shared state of its screen, and the server logs `desync in the menus ...`. Every player sees a desync as a chat line. A screen of a session must change shared state only from the combined input and the server's commands; the local mouse and keys may only draw or send a command (a local cursor change caused the desync of 2026-10-25). A player who is silent for 3 s or leaves holds the ticks (`hold`). The game waits for the player by default, and any player can choose in a window (`=drop_computer_SLOT`, `=drop_give_SLOT_PEER`, `=drop_stop_SLOT`). `=drop_wait_SLOT` still works but has no button. The server keeps all final ticks: a returning player and a resumed session (`=resume` in the lobby) run them again to catch up (flow.update runs up to 40 menu ticks a frame). The ticks stay held meanwhile, and every client shows a progress bar (the server messages `progress` and `caught_up`). A stopped session is saved in the server's config.json as hex text (`saved_session`). A client that catches up runs far behind its newest final tick, so nothing may drop ticks that it has not run yet. A new name in a running session watches it (a spectator, 30 ticks behind). The server has a main room and private rooms (`create_room`, and `join_room` with a code of four characters, or `=create_room` in a lobby trace). Its log prefixes a private room's lines with `[CODE]`.
- Online tests: `tools/test-online.sh` (87 checks, headless: a versus game with a second fight, stage mode, the title's Quit back to the lobby, the game speed, a player who leaves, a drop, "give the fighter", a return, a return that leaves again while it catches up, stop and resume, a spectator, two rooms, the setup screen in a session with the values of the last match, a click and then keys on the setup screen) and `tools/test-online-ui.sh` (36 checks, two windows on Xvfb: host and join through the menus, the session at the setup screen, the chat in the menus and in a fight, taunts, the settings menu that does not stop the fight (also after a fast Escape, Escape), the computer control, the leave question, the server that stops with a crashed host). Run both after a change to the network code, the chat or the menus. tools/test-online.sh runs its scenarios at the same time (about a minute; `JOBS=N` limits them, `SERIAL=1` runs them one after another) and shows a progress bar on a terminal, and both scripts can run at once. `KEEP=1` keeps the logs and screenshots. A frame that waits for the server runs the scripts again: code before the exchange must not count frames, and its sounds and draw commands are lost (play them after the exchange).
- The fight screen of this computer (docs/fight-screen.md, docs/camera.md): the battlefield layout `classic` (the original picture and status panel) or `modern` (the default; older configs with `expand` or `dynamic` become `modern`). The new screen uses the whole window: a card for each fighter (base/ui/fight_hud, Dear ImGui with the engine elements `bar`, `group` and the flags `compact` and `small`), the world in the middle of the rows under the cards, boss bars in Stage mode, and panels (base/ui/panels: the damage share, the input timeline, the stage panel, the minimap) that move anywhere in the window and keep the nearest corner as anchor (config.json `panels`). The camera (base/ui/camera_view) frames the fighters up to `camera_widest` percent of the window, or holds the player's zoom (`camera_zoom` percent, 0 for automatic): the mouse wheel (the engine's ` z` input token), Page Up and Page Down zoom, Home goes back to automatic. The widest view is the whole stage, and Stage mode's closed part shows darker. It draws through the scaled render area (`context.render_area(x, y, w, h, ax, ay, scale)`), and the HUD draws as overlay. It must never write to the fight: the same trace must give the same description with `classic` and `modern`. The player colors of Age of Empires II by slot (base/ui/player_colors) show on the cards, the names, the chart and the setup screen.
- Escape opens the settings menu (base/ui/fight_menu, pages Game, Sound and Display) in a fight and in a network game. The menu never stops the fight, and closing it never resumes one: only F1 (also its Pause button) pauses. This computer's keys are held back while it is open. Its "let the computer play" button puts the letter `A` into the player's keys (base/game/match `read_control`), so a trace can test it with `#27` and then `=control_0`. The fight description shows `computer=1` on such a fighter.
- Sound is local to each computer: the options `music`, `music_track`, `music_volume` and `sound_volume` in config.json. F11 and F12 change the music volume by 10 per press.
- Menus with Dear ImGui (the network menu, the lobby, the chat during fights, the match setup screen, the settings menu): a screen describes its menu in draw() with base/ui/imgui.lua, the engine draws it at the window's resolution (src/adapters/sdl/platform.cpp `draw_ui`), and the clicks and typed text come back in the next frame's input (`input.ui`). Headless runs draw no menus.
- Windows builds run in Wine: `WINEPREFIX=<scratch prefix> wine build/windows/openlf2.exe ...`. Pass Windows paths, for example `Z:\home\...`.
- For screenshots, run the game under `Xvfb :97` with `SDL_VIDEODRIVER=x11` and `--renderer software`, drive it with xdotool (focus the window first) and capture with `import`.

Do not use port 12345 for tests when a real game hosts on this machine.

## Architecture

docs/architecture.md shows the parts, one frame, the network game and the game versions in diagrams. docs/ai.md describes the current AI (game/ai.lua, a port of the original that must stay exact for the replays), and docs/ai-plan.md the new AI framework. docs/ai-moves.md lists the moves of every fighter: regenerate it with `tools/lf2_moves.py FOLDER`, where FOLDER holds data/data.txt and the .dat files (~/games/LF2 on this machine).

- src/app/application.cpp parses the arguments, opens the window, loads the installer and runs the frame loop. src/app/versions.cpp installs and switches game versions.
- src/adapters/ holds the libraries behind small interfaces: SDL3 (window, input, sound, and Dear ImGui for the menus), LuaJIT (script runtime), curl (downloads), FFmpeg (music), the TCP transport, ENet (UDP messages) and miniupnpc (UPnP).
- scripts/runtime/bootstrap.lua is trusted. It loads the game modules into a sandbox (no files, no OS and no native code, only the `engine` table) and passes frame commands to the engine.
- scripts/base/ holds the game. ui/flow.lua routes the screens and runs the network exchange, the settings menu, the catch-up, the input buffer and the overlays. game/match.lua runs a fight. game/server.lua is the server program, and game/online.lua is its client. game/setup.lua and ui/setup_screen.lua are the match setup. game/network.lua is the old two-computer protocol, including script sharing and the version line.
- The network game runs through the server program. The server makes each tick final, and every client runs the whole game on the final ticks: the menus in lockstep, the fights with rollback. The old TCP game (`--host`, `--join`) is a lockstep of two computers: on each frame both send their keys and run the same frame with the combined keys.

## Rules

- Fight state lives in the match table, never in a module variable: a rollback saves and restores only the match table (base/game/rollback), so a module value that a fight changes differs after a client goes back over a tick. The random fighters of Stage mode were such a value (the desync of 2026-10-25, now `match.stage_random`). `--rollback-check` with a smaller `rollback.interval` (for example 9) runs almost every tick twice and finds such state.
- Determinism: everything that changes a fight (keys, speed, random numbers) must be the same on all computers. It comes through the combined input or the shared random generator (`engine.random`). Never use `math.random` (the sandbox removes it). Screens and overlays that only draw can use local data, such as the local mouse.
- The network profile is a SHA-256 of the script bytes and bootstrap.lua. Keep LF line endings, or two computers do not match.
- Script sharing sends the sandboxed modules, never bootstrap.lua or the engine. A host can send scripts to an older engine, so check new engine functions before use (`if engine.versions then`).
- The engine allows 1048576 frame commands (src/adapters/luajit/runtime.cpp, bootstrap.lua). The released Windows build allows 4096. ui/flow.lua counts the commands and keeps them under `engine.frame_command_limit`.
- Overlays (damage chart, input timeline, fight effects) only read the match state.
- Comments: follow the style of the file. Explain why, and name the original behavior when a rule copies it.
- Commits: conventional commits (`type(scope): description`). The commit body ends with the `Signed-off-by:` line of the owner.
